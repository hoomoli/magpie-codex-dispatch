# 插件后台持有、桌面显示与会话归档流程

## 这份文档说明什么

会话出现在 Codex 桌面中，不代表桌面必须取得执行权。插件可以在自己的后台执行任务，由桌面跟随显示对话和进度。

**2026-11-06 已在本地测通的流程是：后台创建并执行任务 → 任务结束后继续持有会话 → 桌面跟随显示 → 原后台执行归档 → 通知桌面 → 释放资源。**

本文同时记录最初的临时验证和后续未发布版本 `0.0.8-local.5` 的实现、安装态验证结果。两者分开记录；本地验证通过不等于真实 Claude 完整验收通过，也不等于可以发布。

## 各方负责什么

| 角色 | 职责 |
| --- | --- |
| Claude 等调用方 | 通过插件发起任务、查询状态和请求归档。调用方本身不是会话的写入持有者。 |
| 插件后台 | 保持拥有会话的执行连接，处理任务和桌面转发的操作，并通过原连接执行归档。 |
| Codex 桌面 | 显示会话、接收进度更新。作为跟随者显示时，无需接管执行权。 |

这里的“持有”指后台拥有会话的写入与执行连接，不是窗口焦点或当前选中的聊天。“app-server”是提供会话执行接口的后端进程。本方案保持插件自己的后端运行，不要求桌面与插件共用后端，也不要求特殊的桌面启动方式。

## 通用操作流程

1. **创建并执行。** 调用方通过插件创建任务，插件后台取得会话执行权，并将更新提供给桌面。
2. **桌面跟随显示。** 用户可以打开会话查看结果，也可以切换到其他聊天。不能只凭侧栏可见或已打开，就判断桌面已接管。
3. **完成后继续持有。** 任务完成后，原后台继续运行，等待后续任务、归档或明确交接；不因为完成计时到期就自动退出。
4. **归档请求回到原后台。** 插件确认实际持有者，并将请求交给原后台处理。归档前必须确认会话空闲，没有待回答问题、审批或其他冲突操作。
5. **确认归档再通知。** 原后台通过自己的执行连接提交归档，收到服务端成功回执后，再通知桌面更新列表。通知本身不能代替归档。
6. **释放资源并核实结果。** 记录结果，关闭相关连接并释放资源；独立核对普通列表、归档列表和历史可读性，再由用户确认侧栏是否自动消失。

核心原则是：**先由原持有者完成归档，再释放持有。** 只让后台一直运行、却不提供请求回到原后台的通道，并不能让归档功能自动可用。

归档保留历史，不等于永久删除。本轮流程未验证永久删除。

## 最初两轮实测

使用专用、无害的测试会话，没有操作业务会话。

| 场景 | 实际观察 | 能说明什么 |
| --- | --- | --- |
| 旧版本后台正常退出 | 执行中及刚完成时为 `owner:background`；后台退出后，再次查询为 `owner:desktop`。实际调用插件归档返回 `owner_action_required`、`submitted:false`。 | 提前释放原后台可能让桌面接管，从而阻止插件通过独立后端归档。不能推断每次打开或退出都必然接管。 |
| 原后台继续持有 | 临时进程复用仓库的后端、后台运行和桌面跟随模块，取消完成后的退出计时。用户打开过会话；采样发现跟随者和同一写入进程。完成 79 秒后，实际安装插件的所有权查询仍返回 `owner:background`。 | 超过旧版本约 60 秒的保留期后，后台仍可持有，桌面仍可跟随。 |
| 原后台归档 | 原连接仍持有会话时提交 `thread/archive`，收到成功回执后发送真实归档通知，再退出。 | 无需先交给桌面，也无需另起后端抢回执行权，即可归档这条空闲会话。 |
| 独立核实与界面观察 | 普通列表中不存在、归档列表中存在、历史可读、无写入持有者；用户确认普通侧栏已自动消失。 | 本次归档、资源释放和侧栏移除均成功。 |

保留后台的那一轮使用临时验证进程，没有修改安装态插件，也没有用官方桌面归档工具兜底。用户只短暂打开过会话，未验证连续停留 90 秒；跟随关系和所有权采用采样检查，没有逐瞬间监控。

## 本地 `.5` 版本如何实现

以下为后续实现记录，版本为未发布的 `0.0.8-local.5`。

- **持有与容量。** 新后台不再按完成计时退出，直到明确归档或空闲交接。同一状态目录最多容纳 8 个后台，创建会话前通过整个存活期间持有的内核锁限制容量。忙碌或状态未知的后台也占容量；达到上限返回 `OWNER_LIMIT_REACHED`，不驱逐已有会话。幂等回执保留，不自动清理。
- **控制通道。** 后台在插件状态目录发布私有、带版本的控制描述文件，并在短路径私有临时目录提供经过认证的套接字。路由前检查权限、进程身份、实例令牌和实际写入进程。令牌与端点路径不进入公开工具结果。这是插件自己的通道，不是共用桌面后端或冒充原生工具调用方。
- **归档路由。** `codex_archive` 独立枚举并锁定已保存的会话及发现的后代，确认实际后台持有者，再交给原后台。后台将归档与桌面转发的修改操作串行处理，重新检查空闲状态、待处理请求、原写入进程与后代范围。后代仍被持有时拒绝；后代集合变化时重新预检。桌面或未知持有者仍返回 `owner_action_required`，不尝试抢占。
- **结果与重试。** 调用端和后台在提交前都持久化操作意图。后台先记录成功回执，再为已检查范围发送真实的 `thread-archived` v2 通知。成功记录可供调用端断线或插件重载后查询、重放，不重复提交。后端回执丢失时保留未知结果，并在该持有者存活期间阻止后续修改。明确的服务端拒绝保留在原请求下，不自动重试，会话仍可执行任务。
- **资源释放。** 归档确认成功或明确空闲交接后，后台发送响应，关闭桌面、控制和后端连接，移除自身描述文件及套接字目录，释放容量锁和后台锁。成功回执后即使响应发送失败也要清理。桌面通知失败单独报告为 `desktopNotified:false`，不能称为界面验收成功。
- **明确交接。** `codex_handoff` 先请求已核实且空闲的后台释放，再沿原流程等待桌面接管；忙碌或有待处理请求时拒绝。交接后，该会话不再适用原后台归档。旧后台不会因插件重载自动获得新控制协议，仍沿用旧退出行为。
- **重载与异常。** 重载或禁用 Magpie 插件不会关闭已分离运行的后台，重载后的调用端通过描述文件重新连接。后台崩溃、系统退出或后端断线不能自动恢复。过期描述文件不能证明所有权，写入进程不匹配时拒绝路由。未知结果须先核实。8 个后台的上限只约束单一状态目录下的并发后端，不代表限制所有状态目录的总资源或历史回执数量。

自动化检查包括 `node --test test/owner-lifecycle.test.js test/flows.test.js`、`node scripts/verify-retained-owner.mjs`、`npm test` 和 `npm run check`。隔离的真实后端脚本不启动模型任务，不使用官方桌面归档兜底，检查存储、回执重放以及写入和套接字释放。界面刷新和真实 Claude 调用须另留证据。清理验收规则更新为 `archive-retained-owner-v2`，要求真实 Claude 通过 Magpie 完成原持有者归档。

## 安装态插件验证记录

实际安装版本报告为 `0.0.8-local.5`，模块地址指向本仓库。

### 接口验证

Codex 通过 Magpie 创建 `MAGPIE-QA-LOCAL5-API-SMOKE-1106`（`<private-fixture-id>`），核实后台写入持有者，再通过 `codex_archive` 请求归档，请求 ID 为 `<private-request-id>`。

回执包含 `route:background-owner`、`serverAcknowledged:true` 和 `desktopNotified:true`。同 ID 重放和操作状态查询成功。独立检查确认普通列表不存在、归档列表存在、历史可读、无写入持有者和控制描述文件，后台及后端进程均已退出。未使用原生归档兜底。调用方为 Codex，不是真实 Claude。

### 持有与侧栏验证

观察会话 `MAGPIE-QA-LOCAL5-RETAIN-1106`（`<private-fixture-id>`）输出 `LOCAL5-OWNER-READY`。完成超过 60 秒后，实际写入进程仍与原后端一致，插件重载后仍为后台持有。

用户在有意保留阶段确认“确认了，还没消失”后，Codex 才调用实际插件归档，请求 ID 为 `<private-request-id>`。原后台返回 `route:background-owner`、`serverAcknowledged:true`、`desktopNotified:true`。独立检查确认存储状态正确、无写入持有者和描述文件，相关进程退出。用户在没有手动刷新、归档或删除的观察步骤中确认“已自动消失”。人工界面观察与服务端回执分别作为证据。

该会话创建早于开发中新增的可选控制状态诊断，因此旧后台没有可选状态命令，但归档控制可用。冻结源码后的完整验收必须创建全新测试会话。

**安装态后台持有、归档和侧栏验证通过；真实 Claude 完整验收仍阻塞、尚未执行，发布门禁未开放。** 临时验证结果不代替本轮安装态证据。私有回执与复核记录保存在按日期组织的 `magpie-retained-owner-local5` 审计目录。

## 后续可重复执行的验证步骤

1. 创建标题明确的专用测试会话，执行无文件改动、带固定完成标记的无害任务。记录会话 ID、任务轮次 ID、原写入进程和开始时间。
2. 确认后台执行、桌面可见，并查询实际所有权为 `background`。侧栏可见不能代替所有权检查。
3. 打开会话观察结果，再切换到其他聊天。观察者无需一直停留，也无需同时保持打开并回复。记录显示情况和跟随连接。
4. 完成后保留原后台，由测试执行方等待超过旧退出阈值，并在阈值前后核实同一写入进程和实际所有权。无需让用户承担计时等待。
5. 确认空闲且没有待处理输入或审批，通过正式插件请求原后台归档；结果明确前继续保留原连接。
6. 检查成功回执、真实桌面通知及资源释放。独立核实普通列表不存在、归档列表存在、历史可读、写入持有者释放。
7. 用户确认侧栏是否自动消失。未观察到或侧栏残留须单独记录，不能以存储成功替代界面成功。
8. 重复原请求检查幂等性，核实结果可查询且不重复修改；按对应验收方案补测忙碌拒绝、并发、失败、断线、未知结果和重载边界。

先让用户完成显示观察，再执行归档。归档成功同时完成测试会话清理。失败时保留会话 ID、说明剩余清理项，不暗中切换到桌面工具或删除操作，并把兜底结果算作插件成功。

## 已知边界

- 最初架构验证仅覆盖单个空闲会话和有限时间的持续持有，不证明无限期持有、所有并发情况、后代会话行为或系统重启恢复。后续实现的自动化检查与安装态结果须分别判断。
- “始终不打开”和各种“打开后切换”的操作组合尚未形成完整对照矩阵，不能据此保证所有桌面版本、所有操作下的所有权行为。
- 后台已崩溃或桌面已接管时，不能凭本次成功推断插件可以抢回执行权。归档结果未知时，必须先核实再决定后续操作。
- 永久删除未测试；归档成功不表示删除可用。
- 本地流程通过不代替真实 Claude 到 Magpie 的完整验收，不自动构成发布授权。

原始验证环境为 ChatGPT/Codex 桌面 `26.1027.61615`、内置 `codex-cli 0.166.0-alpha.5.1`、插件 `0.0.8-local.4`；安装态后续验证为插件 `0.0.8-local.5`。相关版本升级后需要重新核实兼容性。
